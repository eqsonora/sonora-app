# Contributing to Sonora

Thank you for wanting to help. Sonora's source code is private, so this is not
a repository where you send code. It is where you tell us what you think, and
that shapes what gets built next.

## Share an idea or an opinion

Every idea is welcome, small or large: a feature you miss, a page that
confuses you, a sound you cannot get, a thing you would remove.

1. Search [Discussions](../../discussions) first. If someone had the same idea,
   add a comment or an upvote there: one busy thread says more than five
   scattered ones.
2. Otherwise open a new discussion in **Ideas**. Say what you were trying to do
   and what got in the way. "I want to switch presets when my headphones
   connect" is more useful than "add automation".
3. For questions, use **Q&A**. For anything else - your setup, what you listen
   on, what you like or do not - use **General**.

Ideas are read. Not all of them become features, and when one does not, we try
to say why.

## Report a bug

- **The fastest way** is the feedback button inside Sonora: it attaches a
  screenshot and the technical details we need, and nothing is sent until you
  press send.
- Or open an [issue](../../issues/new/choose) with the **Bug report** form.
  Include your macOS version, your Sonora version (Options -> Updates), the
  audio output you use, and the steps to make it happen.

Please **do not paste** licence keys, account emails, API keys or anything
from your keychain into an issue. We never need them to fix a bug.

## Ask for a headphone model

Use the **Headphone request** issue form, or "Ask for a headphone" inside the
Headphones page of the app. A model is added when a measurement we can trust
exists for it.

## Improve a translation

The app speaks twelve languages, and some of them are better than others. If a
sentence reads wrong in your language, open a discussion or an issue with:

- the language,
- where the text appears (page and control),
- what it says now, and what it should say.

## Improve these documents

This repository only holds documentation and images, so pull requests are
welcome for typos, unclear sentences and outdated information in these files.
Keep them in plain English and avoid em dashes; a hyphen does the same job.

## Security

Do not open a public issue for a vulnerability. See [SECURITY.md](SECURITY.md).
